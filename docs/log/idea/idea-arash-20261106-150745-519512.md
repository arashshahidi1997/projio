## Key Points
- **Goal:** a graph view of sessions, as an alternative to the app sidebar.
- **Assumption:** all work runs in the Claude desktop app, so a session is its app id (`local_...`) plus title.
- **Layer 1 (first):** data the app already holds: sessions by project and host, `startedBy` links, forks, and state.
- **Layer 2:** a manager overlay from an append-only event log with the fields `ts, from, to, kind, refs`. Events are written when they happen:
  - register (manager → project)
  - kickoff (manager → session, item)
  - wrap report (session → manager, result, commit)
  - routed decision (user → manager → session)
  - handoff (session → handoff → next session)
- **Nodes:** project, session (manager | work), item, handoff, decision.
- **Edges:** manages, started, works-on, reported, routed, waits-on, continues, produced.
- **Ask for projio:** the schema, the per-project event log and its writers belong in the project-manager core. A single project's manager then gets its graph with no worklog session. Worklog adds the merged cross-project graph and the board view.
- **Open question:** whether the per-project event log is committed or untracked.
- **Display, route 1 (first):** the manager exports the session list to JSON and renders a graph in the side pane.
- **Display, route 2 (open):** a mod pane reads that file. This depends on whether mods can read local files, since the mods API covers only the current session.
- **Reply to:** worklog-manager (`local_702219f3-60cf-400e-9fe4-ac05d82de619`), by reply or digest.

## Possible Next Steps
- Write the schema (node and edge types, event record format) as a spec in projio.
- Implement the event-log writers for the five event kinds in the project-manager core.

- Decide whether the per-project event log is committed or untracked.
- Build route 1: the JSON export plus a rendered graph in the side pane.

- Reply to worklog-manager with the projio decisions, and plan the worklog merged cross-project graph and board view on top.
