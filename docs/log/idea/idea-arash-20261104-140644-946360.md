# [from lit-studio, R58] Brainstorm: cover run-record provenance and automatic claim review better than Claude Science

## From

**lit-studio**, formerly journal-club: the user's knowledge base for the field and analysis methods, and the talks made from it (`/storage2/arash/projects/lit-studio`; background: `docs/for-other-projects.md`). Filed 2026-11-04 at the user's request, during the run `backlogs/2026-11-02-pixecog-consultation.md`. The same note went to projio (R58) and agentic-workshop (R59).

## Problem

Anthropic released **Claude Science** (beta, 2026-06-30), a desktop app that pairs Claude with an analysis environment. Its strong side is the layer that the projio stack and the agentic workshop exist to cover: tracing each analysis output back to what ran, and checking the agent's claims against that record. lit-studio compared it with its own tooling and was corrected by the user: run records and provenance are your job (projio/pipeio, Marimo, Snakemake, Pixi, Git/DataLad, BIDS), not lit-studio's or biblio's. The user wants a **brainstorm session** on how to cover these needs better than Claude Science does.

## Evidence

How Claude Science works, from its docs (`https://claude.com/docs/claude-science/overview`, pages "Artifacts", "The reviewer", "Core concepts", "Tools and environments") and from the install on the user's laptop (`~/.claude-science/runtime/0.1.49-release/`, version 0.1.49, installed 2026-09-17; not on gamma2):

- **Own harness, not Claude Code.** A local web app (`claude-science serve`), a bubblewrap sandbox with deny-by-default network, permission cards per folder, host, connector tool and remote job. Persistent Python and R kernels; a `repl` tool with a `host` SDK (`host.mcp`, `host.delegate`, `host.archive`); `generate_plan`, `save_artifacts`, remote jobs over SSH/Slurm or Modal.
- **Provenance per artifact version** (stored in `~/.claude-science`, one machine, SQLite): five tabs — Messages, Code (a script rebuilt from the cells, downloadable as script or notebook), Execution Log ("the authoritative record of what ran"), Environment (package list with versions), Review.
- **Automatic reviewer** (`agents/reviewer/metadata.yaml`): started by a review orchestrator after responses and periodically during long work; no code execution; reads transcript, execution log and artifacts. "Trace, don't recompute." Fails a claimed action with no matching tool activity, a value that contradicts tool output, a figure caption its own data contradicts, a misquoted source in the session, an unsound method for the stated claim, a missing planned deliverable. Does not flag values it can't trace — except external citations (DOI, PMID, "Author et al. YEAR"), which are flagged when they trace nowhere. Users add their own criteria; "specialists" (named sets of skills, connectors and instructions) extend it.
- **Skills** are standard `SKILL.md` folders (Apache-2.0) with a `kernel.py` auto-loaded into the kernel; connectors are MCP servers (a bundled `bio-tools` server wraps public databases).

Comparison with the workshop stack (lit-studio's reading of `agentic-workshop/2026-10/spec.md`):

| Claude Science | Workshop / projio stack | Stronger |
|---|---|---|
| Persistent kernel | Marimo reactive notebook | Marimo: no hidden state, no stale cells |
| Code tab, rebuilt from cells | `src/` module + Snakemake rule | Stack: code is written as code |
| Execution log per artifact | Snakemake DAG, `snakemake --report`; `datalad run` (deferred in the workshop) | Stack, for pipelines |
| Environment package list | Pixi lock file | Stack: re-solvable |
| Versions in a local SQLite database | Git/DataLad history, siblings, RIA | Stack: portable; "a fresh agent can clone and reproduce" |
| — | BIDS, `derivatives/` | Stack |

Where Claude Science does more:
1. **Exploration gets provenance without effort.** Every ad-hoc cell is recorded and tied to the artifact it produced. In the stack, provenance starts when work is promoted to a rule or a `datalad run`; before that, a Marimo notebook has only its git commits.
2. **Claims are checked against the run record automatically.** The workshop's check on an agent's change is `git diff`, read by a person.
## Request

A brainstorm session with the user (lit-studio and agentic-workshop can join) on how projio covers these two gaps, and better than Claude Science. Questions to start from, not answers:

1. **Exploration provenance:** can a Marimo session's runs (cell, inputs, outputs, environment) be captured without asking the user to promote first — e.g. via `pipeio_nb_snapshot` / `pipeio_nb_extract`, `datalad run` wrapping, or a run log kept next to the notebook — and land in git/DataLad rather than a local database?
2. **Output → run tracing:** one way to ask "where did this figure/number come from?" across notebooks and flows (Snakemake provenance, `datalad run` records, pipeio's registry).
3. **Automatic claim review:** a reviewer agent (Claude Code subagent, started by a Stop/SubagentStop hook or a pipeio tool) that checks claims in a notebook, report or wiki result page against the Snakemake log or `datalad run` records, using a rubric like Claude Science's (trace, don't recompute; contradictions convict, untraced values don't; external citations always checked).
4. **What to borrow directly:** the reviewer prompt and the Apache-2.0 skills are readable on the laptop under `~/.claude-science/runtime/0.1.49-release/` (`agents/`, `skills/`).
