> Raw idea (verbatim): *"file system for project dev inspired by how brain collects and stores information."*

## Problem / motivation

Research repositories accumulate heterogeneous artifacts — raw captures, scratch notes, decisions, code, methods, figures, references, results — and most folder conventions either collapse them all into one bucket (chaos) or force premature taxonomy (over-organization). The brain solves this by having **functionally distinct memory systems** (sensory, working, episodic, semantic, procedural, associative) that share a consolidation lifecycle. A filesystem layout that borrows this *functional* architecture — without literally imitating biology — could give humans **and** AI agents a stable, queryable substrate where each artifact has an obvious home and an obvious next step.

This is the missing conceptual frame underneath projio's existing structure (`docs/log/`, `docs/reference/`, `code/`, `.projio/`, codio/biblio/notio): we already have most of the pieces; we lack a clean cognitive-architecture story that explains *why* the layout is shaped the way it is and *what rule* governs movement between layers.

## The proposed mapping

| Brain function | Repo analogue | Lifecycle role |
|---|---|---|
| Sensory buffer | `inbox/` (raw notes, screenshots, voice, pasted refs) | Capture, never organize at write-time |
| Working memory / PFC control | `active/` (current_goal, scratch, hypotheses, blockers) | Small, volatile, "what matters now" |
| Episodic memory / hippocampus | `log/` (dated session logs, decisions/) | Append-only trace of how knowledge emerged |
| Semantic cortex | `docs/` (concepts, methods, architecture, tutorials) | Consolidated, slow-changing understanding |
| Associative cortex | `memory/` (claims, entities, maps, open_loops, lessons) | Linked retrieval layer with evidence + status |
| Procedural memory / basal ganglia | `workflows/` (Snakefile, rules, configs, envs) | Reusable action — "how I do this again" |
| (data + outputs are bulk storage, not memory) | `data/`, `outputs/` | Substrate, not cognition |

## The single core rule

**Capture → bind → consolidate → retrieve.** Every idea first lands in `inbox/` or `log/`; only consolidated knowledge graduates to `docs/` or `memory/`; only repeated actions graduate to `workflows/`. A weekly consolidation pass (empty inbox, summarize logs, promote stable knowledge, update open_loops) is the analog of **systems consolidation** during sleep.

The filesystem stays a **shallow tree**; associations live in metadata and links (graph over hierarchy). This matches how the brain layers a coarse anatomical hierarchy on top of a dense association graph.

## Why this is interesting now

The pieces are converging in active communities, but **no one is combining them**:

- **PARA / Johnny.Decimal / Building a Second Brain** — action-oriented information architecture, but not memory-system-shaped.
- **Zettelkasten / evergreen notes (Andy Matuschak)** — strongest lineage for semantic memory and association, but personal-note-focused, not project-shaped.
- **Local-first Markdown + LLM memory** — Basic Memory, memex-kb, SwarmVault, Claude Code "Memex" Obsidian plugin — closest to projio's substrate (plain files + YAML + SQLite/embeddings + MCP), but they target generic PKM, not research projects with code/data/workflows.
- **Academic PKM research (2025)** — Obsidian "second brain" retrieval study; NoteBar (persona-conditioned auto-organizing notes). Components are being studied; no synthesis yet.
- **Memex (Vannevar Bush)** — the philosophical root: associative personal information machine.

The gap: a **cognitive architecture for research projects**, implemented as a local-first filesystem for humans + agents, that combines memory-system separation, capture-to-consolidation lifecycle, episodic logging, semantic docs, procedural workflows, agent-readable metadata, and reproducible code/data structure.

This is exactly the territory projio + worklog already occupy — but framed implicitly. Naming the frame would clarify the design, give skills/MCP-tools obvious slots, and become a teachable artifact for the [[idea-arash-20260507-221835-382557]] handbook + workshop initiative.

## Success criteria

- A short essay / handbook chapter that:
  1. Names the seven memory systems and their repo analogues.
  2. States the single consolidation rule.
  3. Shows a minimal worked example (one repo, one week's flow from `inbox/` → `log/` → `docs/` → `memory/`).
  4. Maps the frame onto existing projio surfaces (notio = episodic+working, codio = procedural+semantic over code, biblio = external reference memory, pipeio = procedural, indexio = retrieval substrate, memory/ = associative).
- A reference layout (skeleton repo) demonstrating the convention.
- Optionally: a `projio init --kind cognitive` flavor (or doc add-on) that scaffolds `inbox/ active/ memory/` alongside the existing layout.
