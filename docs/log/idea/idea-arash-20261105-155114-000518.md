## Key Points
- **Where to change it:** `src/projio/data/skills/project-manager/SKILL.md`, in the "Two forms" section (registering) and either "Report-back protocol" or a new "Digest up" section.
- **Background:**
  - worklog-manager is a standing session on the laptop, above the project managers.
  - Design: worklog `docs/specs/worklog-manager.md`. Adapter: `.claude/skills/worklog-manager/SKILL.md`.
  - Managers find each other through an id registry owned by worklog. It is the untracked `workflow/managers.yml` on gamma2, accessed with `worklog manager register|get|list` (forwarded to gamma2 from the laptop).
- **Step 1, register at start:** `worklog manager register -p projio --name projio-manager --session <own id from get_session("self")>`. Re-register after every restart.
- **Step 2, send a digest:**
  - When: at the end of a round that changed something, and immediately for a new decision for the user or a new blocker.
  - Look up the target id with `worklog manager get worklog`.
  - Check it with `get_session`. Archived, missing, or a different title means stale.
  - Send with the app's `send_message(session_id=...)`.
  - Fallback if stale or the send fails: `worklog note -p worklog -k idea --no-llm "[from projio] digest ..."`.
- **Digest format (fixed, nothing else):**
  ```
  digest · projio · projio-manager · YYYY-MM-DD HH:MM
  finished: in plain words, ids in brackets | none
  decide: question in plain words; options, recommended first | none
  blocked: what, waiting on whom | none
  needs: project: what it needs from it | none
  next: one line
  ```
- **Inbound from worklog-manager:** only the user's routed decisions, in the form "decision · projio · item / the user chose: ... (date) / record it in: ...".
- **Rules on decisions (user, 2026-11-05):**
  - A relayed decision may be acted on for that exact question only.
  - Anything beyond it still needs the user in the session.
  - A manager's own message is never the user's approval.
- **Manager-to-manager messages:** questions go direct via registry lookup. Copy worklog-manager only when the answer changes priorities.
- **Scope:** only these two steps in the manager role are added. Nothing else changes.
- **Dependency:** `worklog manager` reaches gamma2 only after worklog's commit is pulled there (the user pushes when they choose). Until then, skip step 1 and use the note fallback for digests.
