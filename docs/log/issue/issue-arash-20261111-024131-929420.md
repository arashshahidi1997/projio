Reported 2026-11-11 by pix-manager after `projio sync --no-index` in pixecog.

The cleanup session (handoff 20261111-022422) removed docs/pipelines/mkdocs.yml from projio's generated gitignore entries, so projects can track the generated Pipelines nav. But the `# >>> projio >>>` block in a project's .gitignore is only written by `_ensure_projio_gitignore` (src/projio/init.py:1143), called from scaffold() (init.py:1313), i.e. `projio init`. `projio sync` never refreshes it, so pixecog's block (line 100) still ignores the file. gecog and msol are in the same state.

Fix: have `projio sync` refresh the managed gitignore block (same entries as init, idempotent; respect a project's lines outside the block), with a test; mention it in the sync output. Then pixecog, gecog and msol re-run `projio sync` and commit docs/pipelines/mkdocs.yml.

## Resolution (2026-11-11, projio-core)

`projio sync` now refreshes the managed block (step 10b, `_sync_gitignore` in src/projio/sync.py, reusing `_ensure_projio_gitignore` from init.py, which gained `dry_run`/`quiet` and returns its action). Lines outside the block are untouched; a missing block is appended. Sync prints `[~] .gitignore: projio managed block refreshed` or `[=] ... up to date`. Tests: `test_sync_gitignore_*` in tests/test_sync.py. Next: pixecog, gecog and msol re-run `projio sync` and commit docs/pipelines/mkdocs.yml.
