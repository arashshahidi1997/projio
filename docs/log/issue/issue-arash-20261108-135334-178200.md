Reported 2026-11-08 by pix-maintenance · MCP env (pixecog WR-C9).

corpus_list fails with "Error executing plan: Internal error: error returned from database: (code: 1) too many SQL variables" when the MCP server runs from the uv projio env (/storage2/arash/infra/uv-tools/projio, chromadb 1.5.8, sqlite 3.50.4), on both PROJIO_ROOT=/storage/share/sirocampus and pixecog. The legacy rag conda env passes (chromadb 1.3.5, sqlite 3.52.0), but pixecog takes 309 s. rag_query, note_create and project_context work in the uv env. Every project on the uv env is affected.

Repro: PROJIO_ROOT=/storage/share/sirocampus /storage2/arash/infra/uv-tools/projio/bin/python3 -m projio.mcp.server, call corpus_list.

Likely cause (manager reading): src/projio/mcp/rag.py:90 fetches every chunk's metadata in one call, collection.get(include=["metadatas"]), to count chunks per corpus; chromadb 1.5.x turns that into a query above SQLite's variable limit. It is also why the rag env takes 309 s on pixecog. Fix options: page through with limit/offset, count per known corpus with where={"corpus": c} (corpora from the indexio sources config), or keep counts in collection metadata at build time. Avoid pinning chromadb.
