biblio OpenAlex import leaves ~486 @article entries with no `journal` field -> breaks mkdocs-bibtex docs build.

In pixecog `.projio/render/compiled.bib` (and `bib/srcbib/imported.bib`), **486 of the @article entries
have no `journal` field**. They're OpenAlex imports (each has `url = https://openalex.org/W...` and a
doi but no venue), e.g. `ye_2026_BrainWide` (doi 10.1126/science.adx1369 -> Science), plus 485 others
(Garcia-Cortadella_2024_Large, andrillon_2011_SleepSpindles, ...). Root cause: the OpenAlex->bibtex
import does not map the venue (OpenAlex `primary_location.source.display_name` /
`host_venue.display_name`) into `journal`.

Impact: `mkdocs-bibtex` raises `pybtex...FieldIsMissing: missing journal in <citekey>` and aborts
`make build` for every **cited** @article that lacks journal. This is a primary reason the pixecog
docs site build fails (last good _site 2026-06-23). Because it fails one-cited-entry-at-a-time it can't
be practically hand-fixed.

Fix options: (a) biblio import: populate `journal` from OpenAlex venue on ingest, and backfill the
existing ~486 (crossref/OpenAlex by doi); (b) make the compile step inject a placeholder venue for
preprints; (c) configure mkdocs-bibtex to tolerate missing fields. (a) is the real fix.

Related pixecog docs-build blockers found same session (may want their own projio treatment):
present_build build/ dirs under docs/ break the monorepo copytree (filed separately), and Quarto poster
projects commit a .quarto cache + figure scripts under docs/ that trip git-revision-date (worked around
with mkdocs.yml excludes). Net: the pixecog site build needs a dedicated repair pass.
