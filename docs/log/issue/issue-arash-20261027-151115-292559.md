pipeio flow scaffold: support a project-configured Snakefile preamble (needed for pixecog provenance include).

pixecog now requires every Snakefile to carry `include: "../_common/provenance.smk"` (run manifests, spec docs/infra/repo-architecture.md §6.3: "The pipeio flow scaffold template MUST include it"). The scaffold Snakefile is hardcoded twice — packages/pipeio/src/pipeio/cli.py ~L795 and src/pipeio/mcp.py ~L646 — with no project hook.

Ask: (1) dedupe the two templates into one function; (2) read an optional project setting (e.g. `.projio/pipeio` config `scaffold.snakefile_includes: ["../_common/provenance.smk"]`) and emit those include lines right after `configfile: "config.yml"`; (3) pixecog sets it to the provenance include. Note pipeio already skips `_`-prefixed dirs in registry scan (registry.py L154/L238), so `code/pipelines/_common/` is safe.

Until this lands, pixecog's `pixi run dstatus` lints for Snakefiles missing the include.

## Resolution 2026-11-10 (projio-pipeio · marimo + preamble)

Done in pipeio `bc3fd10`.

1. The CLI (`pipeio flow new`) and MCP (`pipeio_flow_new`) templates are deduped into one function, `pipeio.mcp._flow_snakefile(flow, root)`. A test asserts both write the same file.
2. It reads `.projio/pipeio/config.yml`, which already holds `profiles.base`:

   ```yaml
   scaffold:
     snakefile_includes: ["../_common/provenance.smk"]   # an include: line each, right after configfile:
     snakefile_preamble: |                               # optional free text after the includes
       ...
   ```
