biblio: `graph_promote` cannot be scoped to a single seed paper — silently sweeps in other seeds' references.

**Symptom (pixecog, 2026-06-25):** Extracted references for one paper (`ye_2026_BrainWide`, true ref count 129 per GROBID/PDF). `biblio_graph_expand(citekeys=["ye_2026_BrainWide"])` followed by `biblio_graph_promote()` promoted 181 new entries — ~100 of which belonged to a *different* seed (`swanson_2025_TopographyPutative`) left over in the shared `graph_candidates.json` from a prior session's expansion. All 181 got tagged with the Ye tag. Required manual GROBID cross-referencing to de-contaminate (54 entries re-tagged).

**Root cause — API asymmetry in `packages/biblio/src/biblio/`:**
- `graph.py::expand_openalex_reference_graph` defaults `merge=True`, accumulating candidates from every seed ever expanded into one shared `bib/derivatives/openalex/graph_candidates.json`. Each candidate correctly records `seed_openalex_id`.
- `graph_promote.py::promote_graph_candidates` filters only by `top_n / min_citations / min_year / max_year / keyword_filter` — it has **no `seed_citekeys` / seed filter**, so it ignores `seed_openalex_id` and promotes the union of all seeds. The MCP wrapper `mcp.py::graph_promote` mirrors this gap (no seed arg), even though `graph_expand`'s wrapper *does* accept `citekeys` → `seed_citekeys`.

Net: there is no safe way to do per-paper reference extraction via the graph path. Single-paper intent + accumulating shared file = cross-contamination.

**Proposed fixes (any one helps, first is minimal):**
1. Add a `seed_citekeys` (or `seed_openalex_ids`) filter to `promote_graph_candidates` + the MCP `graph_promote` wrapper, matching `graph_expand`'s `citekeys`. Filter candidates on `seed_openalex_id` before applying citation/year filters.
2. Apply per-seed tags automatically at promote time (tag each promoted entry by its actual `seed_openalex_id`→citekey) instead of one uniform user tag.
3. Document that `graph_candidates.json` is cumulative; consider `graph_expand(merge=False)` or a `--fresh` flag as the recommended default for single-paper extraction.

**Workaround for now:** use `biblio_grobid` (parses the PDF bibliography directly = exact 129) for single-paper reference extraction, or pass `merge=False` to `graph_expand` and inspect `seed_openalex_id` before promoting.
