[from pixecog] projio skills: stale hardcoded conventions, sync-copy ambiguity, overlap, no usage signal (pixecog workspace refactor, 2026-10-28)

Observations from pixecog's workspace refactor (pixecog docs/infra/workspace-refactor/index.md, decisions WR-D9 and WR-D12). Server and environment requests are already filed separately: issue-arash-20261028-010346-194501 (reduced sirocampus tool set; MCP servers and mkdocs off conda).

1. **Synced skill copies look editable, and an agent edited one.** `projio sync` writes `.claude/skills/<name>/SKILL.md` from a source (for a project-origin skill: `<project>/.projio/skills/<name>/`). The only signs that it is generated are a gitignore, the `.projio-skill` marker, and a comment at the *end* of the file. In pixecog an agent edited the synced copy of `pixecog-flow-setup` and only found out when `git add` refused the ignored path. Request:
   - put a header at the **top** of every synced copy: "GENERATED by projio sync from <source path>; edit the source";
   - and/or write synced copies read-only (chmod 444);
   - optionally, `projio sync --check` to flag synced copies that drifted from their source.
   Related naming confusion: project-owned skills live in `<project>/.projio/skills/`, which reads as "projio's skills". Consider documenting this prominently, or renaming it to something like `.projio/project-skills/`.
2. **Skills hardcode conventions that go stale.**
   - `pipeio-flow-create`, `marimo-session` and `session-wrap` still say `conda run` (pixecog uses pixi);
   - notebook templates referenced the no-longer-existing `notebook_bootstrap` and `utility-promote`;
   - `pipeio-nb-extract` assumes `{flow}/docs/reports/`.
   Request: skills read env and run commands from project config or `runtime_conventions` instead of restating them, and a projio lint checks skill text against the project config (env manager, run command, paths).
3. **The questio skills assume a milestone/status planning model that pixecog didn't use.** Evidence (2026-10-27):
   - only 7 of 241 result notes have a valid `question:`; all 9 questions are `not_started`; no milestone has a date;
   - in 136 transcripts, `px-next` was used 0 times and `px-status` once.
   The working planning layer became per-thread state docs (`docs/analysis/<thread>/index.md`, with stable finding IDs R/I/D/O; skills `px-analysis-log` and `px-analysis-orientation`, the most used at 24 and 12). pixecog decided (WR-D12): a hypothesis registry plus state docs, with questio retired or reduced to the registry. Request: make the planning layer pluggable, and consider upstreaming the state-doc model as a generic projio pattern.
4. **Overlap and aliases.** Project alias copies duplicate generic skills (`px-session-wrap` vs `session-wrap`; `retro` duplicates the wrap step; `px-gallery` is an alias of an alias; `rag-query` wraps one MCP call). Request: a formal overlay mechanism (a project skill declares `extends: <projio skill>` and adds project specifics, the way `pixecog-flow-setup` layers on `pipeio-flow-create`), so projects stop forking whole skills.
5. **No usage signal.** Skill usage had to be counted by hand from transcripts. Request: count skill invocations (worklog could aggregate them), and flag skills unused for N sessions for retirement.

Priority from pixecog's side: 1 and 2 (cheap; they prevent wrong edits and stale commands), then 4, 3, 5.
