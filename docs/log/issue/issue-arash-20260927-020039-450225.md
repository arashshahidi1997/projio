`present_build` build/ outputs under docs/ break the mkdocs-monorepo site build (copytree).

A presentation's generated `build/` dir committed under `docs/deliverables/presentations/<deck>/build/`
breaks `make build` (mkdocs-monorepo-plugin), which `shutil.copytree(symlinks=True)` the whole docs
tree to a temp dir BEFORE the mkdocs `exclude` plugin runs. Two failure modes seen on
`docs/deliverables/presentations/lab-2026-08-21/build/` (2026-09-26):
  - `build/index.html` is a symlink -> `lab-2026-08-21.html` => copytree raises `[Errno 17] File exists`.
  - some figures are mode 0444 (read-only) => copytree raises `[Errno 13] Permission denied`.
The existing `mkdocs.yml` exclude `deliverables/presentations/*/build/**` does NOT prevent this — the
monorepo plugin copies the physical tree first; excludes only filter nav pages. Net effect: the site
build has been broken since the deck landed (last good _site = 2026-06-23; 114 commits unpushed).

This is projio-adjacent because `present_build` generates the offending `build/` (symlinked index.html
+ read-only figs) inside the docs tree. Fix options: (a) `present_build` should not emit build artifacts
under a path the monorepo copies (emit outside docs/, or use a `.`-prefixed dir mkdocs ignores), (b)
emit plain files (no index.html symlink) with writable perms, or (c) document that presentation build/
dirs must be git-ignored / kept out of docs/. Workaround used: stash the deck's build/ dir + chmod figs
writable before `make build`.
