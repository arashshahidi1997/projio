[from pixecog] Two tooling requests from the pixecog workspace refactor (2026-10-27; pixecog docs/infra/workspace-refactor/index.md, decision WR-D9). (The pipeio scaffold provenance-include request is already filed separately: issue-arash-20261027-151115-292559.)

1. sirocampus MCP server duplicates the full projio tool set. In pixecog's .mcp.json, `projio` and `sirocampus` are the same `projio.mcp.server` differing only in PROJIO_ROOT, so ~200 identical tool names load twice into every agent session. pixecog only uses sirocampus for codio, biblio and rag lookups. Request: a way to load a reduced tool set per server (e.g. an env var or config listing enabled subsystems), so the sirocampus entry exposes only codio_*, biblio_*, rag_*.
2. Environment preference is now pixi/uv; conda is legacy. Today the MCP servers (projio, sirocampus, worklog) run from the shared conda env /storage/share/python/environments/Anaconda3/envs/rag, and mkdocs also uses that env. Request: a supported way to run the MCP servers and the docs build from a pixi or uv environment (e.g. `uv tool install projio` or a pixi env), plus docs for projects to switch.
