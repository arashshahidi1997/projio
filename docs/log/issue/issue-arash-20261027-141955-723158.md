`projio sync` crashes in _sync_render_config when render.yml defines multiple profiles.

Repro (pixecog, 2026-10-27): `/home/arash/.local/bin/projio sync`
→ File "projio/src/projio/sync.py", line 274, in _sync_render_config:
  return {"action": "generated", "output": str(out_path.relative_to(root))}
AttributeError: 'list' object has no attribute 'relative_to'

Context: pixecog's .projio/render.yml now defines render profiles (note / report / manuscript, `default_profile: note`; pixecog commit 2512d27). The compiled output is now a list of per-profile files (.projio/render/pandoc-defaults-{manuscript,note,report}.yaml) instead of a single pandoc-defaults.yaml, but the return path still assumes one Path.

Fix: iterate the list (or report all outputs). The crash aborts the rest of sync, so projio.mk / mkdocs config / library registration steps after the render step don't run either.

## Resolution (2026-10-27)

Fixed in projio 0a63a4a: _sync_render_config reports every pandoc-defaults file (dry run too), and sync_workspace catches a render failure so later steps still run. The crash hit every render.yml, not only multi-profile ones, since write_pandoc_defaults always returns a list. Regression tests in tests/test_sync.py; projio sync --dry-run against pixecog now completes.
