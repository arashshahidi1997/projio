pipeio docs_collect: dead links in collected flow docs (found by pixecog's cleanup audit 2026-11-08). (1) The per-flow index template links `report.md` and `changelog.md`, which are often not collected, so about 8 flows' index pages in docs/pipelines/<flow>/ link to missing pages. (2) Relative links written inside code/pipelines/<flow>/docs/ (e.g. `../../calibrate_ieeg_clean/docs/index.md`, `../../../envs/pygfet/index.md`, `../../../../../docs/log/meeting/...`) break after pipeio_docs_collect copies the files to docs/pipelines/<flow>/, because the copy sits at a different depth. About 110 dead-link warnings in pixecog's mkdocs build. Expected: the template only links pages that were collected, and docs_collect rewrites (or warns about) relative links that point outside the collected tree. Repro: pixecog `make build` log, grep "docs/pipelines" + "not found among documentation files".

## Resolution (2026-11-18)

- pipeio `e226bac`, projio `ed5cf17`. After the collectors run, `docs_collect` rebuilds every collected page from its source and fixes its relative links:
  - a link to another collected page (mod facet routed to `mods/`, another flow's `docs/`, `CHANGELOG.md`, `architecture.md`) points at the collected copy;
  - a link to a page under the site's docs dir (`../../../docs/log/meeting/<note>.md`) gets the path for the new depth;
  - a link to a generated page that exists (`report.md`, `changelog.md`, `dag.svg`, `notebooks/...`) is kept;
  - anything else (code files, configs, a `report.md`/`changelog.md` that was not collected) is reduced to its label and returned as `link_warnings` (MCP), `warnings=` (API), or printed by `pipeio docs collect`.
  Links in fenced and inline code are left alone. Unchanged pages are not rewritten.
- The index template still writes the Report/Changelog links. They are kept when the page is collected and dropped with a warning when it is not.
- Fixture test `tests/test_docs_links.py`: strict `mkdocs build` passes; with the rewrite disabled the same fixture fails with 11 dead-link warnings. Note: `mkdocs build --strict -q` passes even with dead links because `-q` hides the warnings strict mode counts.
- Read-only dry run on pixecog (scratch root of symlinks, relative copy of the registry, `export=False`): 171 files collected, 0 dead relative links left out of 82, 16 links re-pointed into `docs/log/`, 53 dropped with warnings. The drops: 14 `report.md` and 7 `changelog.md` not collected; 7 `...` placeholder links in changelogs; 16 atlas PNGs under `preprocess_ecephys/assets/` that do not exist; code files (`code/utils/*.py`, `sub-05_day2_laminar.yml`, a notebook `.py`, a `config.yml`); `code/envs/pygfet/index.md` (missing); `lfp_extrema` `dag.svg` (no DAG collected). Those are source fixes for pixecog. pixecog's git status was unchanged by the run.
