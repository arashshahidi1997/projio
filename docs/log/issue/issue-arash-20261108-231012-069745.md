projio sync's managed .gitignore block ignores every directory named `site/` (a bare `site/` line between `# >>> projio` and `# <<< projio`), not just the mkdocs output. In pixecog this silently ignored a new `.projio/site/` folder (git check-ignore: `.gitignore:101:site/`), so the site plumbing had to go to `.projio/mkdocs/` instead (2026-11-08). Expected: anchor the pattern (`/site/`, or the configured `site_dir` such as `/_site/`) so nested dirs named `site` stay trackable.

## Resolution (2026-11-18)

- `05da5e5`: the managed block anchors root-only entries. `site/` became `/site/` plus the configured `site.output_dir` and `site.mkdocs.site_dir` (e.g. `/_site/`); `.mcp.json` became `/.mcp.json`.
- The block also listed `.projio/site/` itself, which would still have ignored pixecog's folder. projio writes only `indexio_chat_hook.py` there, so the entry is now `.projio/site/indexio_chat_hook.py` and the rest of `.projio/site/` is trackable.
- Left unanchored on purpose: `.snakemake/`, `*.ipynb`, `.ipynb_checkpoints/` (they appear inside flow dirs). All other entries already contain a slash, so git anchors them.
- Since `a4afc40` sync refreshes the block, so `projio sync` in pixecog replaces the old bare line. Tests: `test_sync_gitignore_anchors_old_bare_site_line`, `test_gitignore_root_only_entries_are_anchored`. Checked with `git check-ignore`: `a/site/f` and `.projio/site/f` are no longer ignored.
