# pipeio flow docs: pipeline-docs.md spec + flow_audit + CHANGELOG convention

## Why

Flow documentation on the site was inconsistent: `preprocess_ieeg` had a
thin scaffold-generated `index.md`, `preprocess_motion` had a rich one,
and neither matched the other. There was **no spec file** for pipeline
documentation at all — the convention only existed in the scaffold code
and in the head of the flow author.

Separately, design history was being lost: `theory.md` and `spec.md`
capture current state but not the *why* behind design changes. A
returning developer or supervisor couldn't see what was tried and why
it was abandoned without grepping commits across months. Raised in
[idea-arash-20260413-145305-923913.md](../idea/idea-arash-20260413-145305-923913.md).

The session started by writing the spec first (so the convention is
pinned), then updating the scaffold and adding a diagnostic `flow_audit`
tool, then migrating pixecog's 8 flows end-to-end.

## Highlights

**New spec file**: `packages/pipeio/docs/specs/pipeio/pipeline-docs.md`
— the canonical reference for flow documentation. Covers:

- Source tree layout (`docs/index.md` landing page, per-mod facet dirs
  with `theory.md` / `spec.md` / `delta.md`, flow-root `CHANGELOG.md`,
  `publish.yml`)
- Canonical `docs/index.md` section list (Purpose, Input, Output + Final
  Products table, Mod Chain with Rules column, Design Decisions, Data
  Availability, DAG, Report, Changelog, Known Gaps)
- Mod doc three-facet convention (theory / spec / delta roles)
- Flow CHANGELOG convention: Keep-a-Changelog format at flow root, what
  belongs (strategy shifts, DAG reorganizations, key discoveries) and
  what doesn't (every bug fix, refactors, parameter tweaks)
- Collection pipeline — ordered list of collectors with their
  `publish.yml` gating
- Reference example: `preprocess_motion` (concrete section snippets)

**New MCP tool `pipeio_flow_audit`** — read-only diagnostic. Answers
"is this flow compliant with pipeline-docs.md, and if not what's
missing?" without ever modifying anything. Returns a structured dict
with `files`, `docs.sections`, `mods`, `issues`, `suggestions`, and a
`fix_hint`. Exposed as:

- `pipeio_flow_audit(flow)` — MCP tool
- `pipeio flow audit <flow>` — CLI with pretty output
- `pipeio flow audit all` — project-wide summary with pass/fail counts
- `pipeio flow audit <flow> --json` — machine-readable
- `pf <flow> audit` — shell helper (bash + zsh completion)

**ChangelogCollector + PublishConfig.changelog flag** — `docs_collect`
pipeline now copies `CHANGELOG.md` from flow root to
`docs/pipelines/<flow>/changelog.md` when `publish.yml: changelog:
true`. Nav generator picks it up automatically via the generic `.md`
loop — no nav code changes needed.

**Scaffold richer template** — `mcp_flow_new` now generates the full
`docs/index.md` template matching the spec (10 canonical sections),
plus `CHANGELOG.md` at flow root with the Keep-a-Changelog header stub,
plus `publish.yml` with all collector flags set to `true`. `flow_new`
remains **idempotent**: rerunning it on an existing flow only writes
missing files. This is the designated non-destructive migration path
— no new `migrate` tool was added (would have been overengineering).

## Pixecog migration

`0/8 compliant → 7/8 compliant` across all pixecog flows:

1. Ran `pipeio flow audit all` → saw 8 failures, most needing just
   `CHANGELOG.md` + `publish.yml`.
2. Ran `pipeio_flow_new` on each existing flow (idempotent scaffold
   completion) → added 1 missing file per flow (CHANGELOG.md) in most
   cases; `manifest_assemble` was missing more and got 12 files.
3. Re-audited → 8 flows now had scaffold files; 7 still had missing
   canonical sections in their hand-written `docs/index.md`.
4. Hand-appended missing additive sections (Data Availability, Report,
   Changelog) before `## Known Gaps` for flows with simple structures;
   more extensive rewrites for `preprocess_ieeg` and `preprocess_ecephys`
   whose hand-authored docs used custom section names.
5. Ran `pipeio docs collect` → 91 files collected, 8 changelogs visible.
6. `mkdocs build` succeeded; nav now has 8 Changelog entries alongside
   Overview for each flow.

The remaining 1 non-compliant flow (`preprocess_ecephys`) is missing
`spec.md` files in two mod facet dirs — a content-creation decision
for the flow owner, not a scaffolding problem.

## Decisions worth recording

- **No `pipeio_flow_migrate` tool**. Considered it but `flow_new` is
  already idempotent, so an explicit migrate tool would be a thin
  wrapper with no additional value.
- **Audit never injects content into user-authored docs**. It reports
  missing sections but leaves them for the author. Auto-injection risks
  corrupting prose; the human can do it in seconds with the spec open.
- **`CHANGELOG.md` at flow root, not under `docs/`**. Matches Python
  package convention and separates history-of-decisions (CHANGELOG)
  from current-state documentation (`docs/`).
- **Legacy `docs/overview.md` still accepted** by `docs_collect` as a
  fallback when no `docs/index.md` exists, but new flows should use
  `docs/index.md` directly. Scaffold only creates `index.md` now.
- **Always-on robustness flags for `pipeio_run`** (earlier in session):
  `--rerun-incomplete`, `--latency-wait 15`, `--printshellcmds`,
  `--show-failed-logs`, `--keep-going` (via `keep_going: bool = True`
  default). Plus `--unlock` auto-runs when stale locks exist without a
  live screen session. `wildcards` now correctly maps to snakebids
  `--filter-{key} {value}` (was incorrectly `--config key=value`).
- **DAG SVG auto-writes to `{flow}/.build/dag.svg`** and is picked up
  by `DagCollector`. The DAG link is injected into the source
  `docs/index.md` by `dag_export` itself (idempotent), so the collected
  copy already has the reference.
- **Export / collect boundary**: `nb_publish` and `dag_export` only
  write to `.build/`; `docs_collect` is the sole path to
  `docs/pipelines/`. Fixes the duplicate `nb-X.html` + `X.html` issue.
