# pipeio rename: pipeio_report → pipeio_flow_report, pipeio_nb_report → pipeio_nb_extract

## Why

Two collisions in the pipeio MCP tool surface were causing real agent
confusion, and the snakemake HTML report had no guardrails against
pathological output sizes.

**Collision 1** — `pipeio_report` and `pipeio_nb_report` both sound like
"make a report", but do completely different things:

- `pipeio_report` → runs `snakemake --report` to produce a single HTML
  with runtime stats, provenance, and annotated outputs
- `pipeio_nb_report` → extracts figures/markdown/text from an executed
  notebook for the agent to write a curated `.md` from

**Collision 2** — the `pipeio-report` skill documented only the notebook
extraction workflow, which reinforced the ambiguity. Anyone reading the
skill tree saw `pipeio-report` and expected the snakemake report.

**Motivating incident** — pixecog's `preprocess_motion` flow has 192 SVG
plots totalling 640 MB (trajectory plots up to 40 MB each from dense
polylines). `snakemake --report` base64-embeds every target into the
HTML, so `report.html` was **856 MB** and unusable. The rename above is
paired with a pre-flight size check that blocks this class of problem
before the 5-minute snakemake run.

## Breaking changes

This is a **breaking rename** by projio convention (no backward-compat
aliases — see `packages/pipeio/CLAUDE.md` "Key Conventions"). Callers
must update:

- `pipeio_report(...)` → `pipeio_flow_report(...)`
- `pipeio_nb_report(...)` → `pipeio_nb_extract(...)`
- `pipeio-report` skill → `pipeio-nb-extract`
- `/pipeio-report` slash command → `/pipeio-nb-extract`
- Python import `from pipeio.mcp import mcp_report, mcp_nb_report` → `mcp_flow_report, mcp_nb_extract`

Downstream projio-managed projects will pick up the new names on next
`projio sync` (which regenerates `.claude/commands/` and `CLAUDE.md`).
