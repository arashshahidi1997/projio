## Task

Synthesize a **roadmap** for the handbook + workshop initiative, working
backwards from the September 2026 workshop deadline. The survey (task A)
told you what exists; the layout/spec (task B) told you what's needed; this
task tells Arash **what to do, in what order, by when, and what to cut if
behind**.

This is **planning only**. Do not write chapter prose, do not provision
workspaces, do not file new task notes as files, do not modify code. The
sole output is a roadmap document with proposed actions inline.

## Output

Write one roadmap document to:

`docs/log/result/result-arash-20260508-handbook-workshop-roadmap.md`

It must contain the following sections, in this order:

### 1. Backwards-planned milestone calendar (May → Sept 2026)

Working backwards from the goal note's milestone dates (workspace → announcement →
syllabus → day 1–3 materials → dry run → workshop → post-mortem), produce a
month-by-month table:

| Month | Workshop track | Handbook track | Cross-cutting |
|---|---|---|---|

For each cell: 1–3 concrete deliverables. Be honest about the May–July
competing-claims pressure (TAC III, manuscript) — the calendar must absorb
that, not pretend it doesn't exist.

### 2. Dispatch order for the four pending tasks

Order the existing four pending tasks (workspace provision, PDF move, chapter 1
outline + draft, marimo-WASM prototype) into a numbered sequence with stated
rationale per step. Disagreement with the user's stated order ("provision
first") is fine if the survey/spec evidence supports a different order — but
state the disagreement explicitly with reasoning.

### 3. Proposed new tasks (descriptions only, do NOT file as task-note files)

List task notes that should exist but don't yet, in the format:

> **Title** (priority, blocked-by, target month) — one-paragraph description

Cover at minimum: workshop announcement finalization, syllabus drafting,
each remaining handbook chapter (2–7) draft, manim opening animation,
participant pre-workshop setup checklist, dry-run task, post-mortem task.
For each: a single source note ref, a single goal ref, no full body. Arash
will convert these into task notes himself; you do not write them as files.

### 4. Cadence + publishing rhythm

A short subsection (≤ 150 words) recommending a publishing rhythm for the
handbook + blog: weekly chapter drops? Bi-weekly? Mineault's drip? Willison's
"note → blog" promotion? Pick one and defend it against the project's actual
constraints (solo author, TAC pressure, workshop deadline). Specify what the
rhythm looks like in May, June, July, August, September.

### 5. Resource budget

A table of cross-cutting investments and their ceilings:

| Resource | Budget | Cut threshold |
|---|---|---|

Cover at least: manim opening animation (hours, ceiling), marimo-WASM
explorables (count, build cost S/M/L per chapter), dataset preparation for
workshop exercises, slide design (single shared theme vs per-day), figio
figures specifically authored for the handbook. "Cut threshold" = the date
or signal at which this gets descoped to keep the workshop on time.

### 6. Risk register

Six risks max. For each: name, likelihood (L/M/H), impact (L/M/H), mitigation,
trigger condition that would force the mitigation. At minimum cover: TAC III
overruns May, manuscript writing overruns June, marimo-WASM doesn't embed
cleanly in mkdocs, low workshop registrations (< 6), sirocampus / lab
infrastructure interruption, single-creator burnout.

### 7. Open-question resolution plan

The idea note ends with three deferred questions:
1. Will projio become a public open-source tool with external adopters?
2. Is the blog a section of the handbook site or its own surface?
3. Final public title / handle.

For each: what evidence is needed to decide, by when (latest decision date
without delaying the workshop), what the default-decision is if no decision
is made by that date.

### 8. What gets cut first

A ranked list (5–10 items) of *things you'd cut to protect the workshop
delivery date*, hardest-to-easiest. The first item is what gets cut at the
first sign of slippage; the last is what only gets cut if September is
genuinely at risk. The handbook itself is in this list — be honest about
which chapters are workshop-critical and which can slide.
